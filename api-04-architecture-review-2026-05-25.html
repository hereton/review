Top Recommendation

Start with Candidate 1: Consolidate Error Mapping. It provides the highest leverage — touching all 14 handlers and removing ~280 lines of near-identical switch statements. All subsequent candidates become easier once the handler layer has a clean, thin error-mapping module.

Recommended order

1 Error Mapping → 2 Handler Helpers → 3 Auth Guards | 4 Repo Helpers + 5 Mappers + 6 Logging

Candidates 1 + 2 can run in parallel — both touch handlers but different aspects.

Candidate 3 depends on 2 (shared handlerutil package must exist first). Fixes a security bug.

Candidates 4 + 5 are independent of each other and of 1–3.

Candidate 6 is fully independent — safe to do anytime.

Estimated total impact: ~350 lines removed + 1 security vulnerability closed across 16 handler files.
