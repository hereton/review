1. Remove Hardcoded Database Credentials

Strong
Files:
internal/config/config.go (64 lines)
// internal/config/config.go:54-63
func defaultDatabaseURL() string {
    u := url.URL{
        Scheme:   "postgresql",
        Host:     "10.13.112.3:5432",
        Path:     "/permission-center-nonprod-04",
        RawQuery: "sslmode=require",
        User:     url.UserPassword("postgres", "-Vz*_Vf=}#1sRTD6"),
    }
    return u.String()
}
Problem: Plaintext password embedded at compile time. Binary string extraction, code inspection, or Git history reveals production-like credentials. The Load() function falls back to this default when DATABASE_URL env is empty — deployed containers that misconfigure the env silently use hardcoded credentials.
Solution: Remove defaultDatabaseURL(). Fail fast at startup if DATABASE_URL is empty. For local dev, use a .env file or direnv.

Strong

3. Unify Soft-Delete Strategy

Strong
Files:
internal/model/role.go (38 lines — ONLY model with DeletedAt)
internal/repository/acl_repository.go (lines 163-164, 180-181)
internal/model/user_abac_assignment.go (status lifecycle only)

internal/model/user.go (is_active boolean — 3rd pattern)
// model/role.go:29 — ONLY table with GORM soft delete
DeletedAt gorm.DeletedAt `gorm:"index" json:"-"`
// acl_repository.go:163-164 — must filter BOTH conditions
JOIN roles ro ON ro.id = m.role_id
             AND ro.deleted_at IS NULL    ← soft-delete filter
             AND ro.status = 'active'     ← status filter
// Compare: model/user_abac_assignment.go — status only
Status AbacAssignmentStatus `gorm:"size:20;not null;default:active"` // no DeletedAt
Problem: Three different "is this row alive?" patterns coexist. (1) roles uses GORM soft-delete via deleted_at, requiring a dual filter in every ACL join. (2) ABAC tables use status lifecycle. (3) users uses is_active boolean. GORM's DeletedAt implementation detail leaks into raw SQL at the ACL seam.
Solution: Remove deleted_at from roles. Use status lifecycle consistently. Apply same pattern to users.is_active. Add CHECK constraints for status values.

Title *string `gorm:"size:200" json:"title"` // JWT title; also 4th OU matching level
// model/ou_role_mapping.go:15 — field named "Section" (renamed from title)

Problem: Three names for the same concept: users.title (JWT claim name), ou_role_mappings.section (renamed for "clarity"), mSection (Go parameter). 5. Add Missing FK on ABAC BU References

Worth Exploring
Files:
migrations/000048_create_user_abac_assignments.up.sql (51 lines)
migrations/000049_rename_role_delegations_to_abac.up.sql

// 000048_create_user_abac_assignments.up.sql
-- bu_id has NO direct FK to abac_bus(id)
-- Only has composite FK:
FOREIGN KEY (bu_id, division_id) REFERENCES abac_divisions(bu_id, id)
-- Missing: FOREIGN KEY (bu_id) REFERENCES abac_bus(id)
Problem: user_abac_assignments.bu_id has no direct foreign key to abac_bus(id). BU integrity is only validated transitively through the composite FK (bu_id, division_id) → abac_divisions. If a BU exists with zero divisions, an assignment referencing that BU would fail the composite FK for the wrong reason. Same pattern in abac_delegations. BU referential integrity is an implicit contract.
Solution: Add FOREIGN KEY (bu_id) REFERENCES abac_bus(id) to both tables via new migration.

6. Unify created_by / updated_by Types

Worth Exploring
Files:
internal/model/ou_role_mapping.go (line 20 — BIGINT FK)
internal/model/role.go (line 26 — VARCHAR(100))
internal/model/user_abac_assignment.go (lines 44-45 — VARCHAR(200))

// Three different types for the same concept:
// ou_role_mapping.go:20 — BIGINT FK to users table
CreatedBy uint `gorm:"not null" json:"created_by"` // FK → users(id)

// role.go:26 — VARCHAR(100), stores display name
UpdatedBy string `gorm:"size:100" json:"updated_by"` // no FK

// user_abac_assignment.go:44-45 — VARCHAR(200), different size
CreatedBy *string `gorm:"size:200" json:"created_by,omitempty"`
UpdatedBy *string `gorm:"size:200" json:"updated_by,omitempty"`

// abac_delegation.go:38 — VARCHAR(200), NOT NULL, default 'sync-job'
UpdatedBy string `gorm:"size:200;not null;default:'sync-job'" json:"updated_by"`
Problem: Three types for "who made this change": (a) BIGINT FK → users(id) with referential integrity; (b) VARCHAR(100) name string with no integrity; (c) VARCHAR(200) name string, different max length. Names drift if user renames. Audit trail queries must know which tables store IDs vs names.
Solution: Standardize to BIGINT FK users(id) across all tables. For ABAC sync rows, use a sentinel system user or nullable FK. Join to users for display name at query time.

After — consistent FK
All tables

updated_by BIGINT FK → users(id)
