3. API Layer C

src/lib/api.ts (76 lines — fetch wrapper with typed methods)
src/apollo/client.ts (40 lines — Apollo Client REST-only setup)
▶ Anti-patterns 4
High Apollo Client for pure REST (overkill)

apollo/client.ts sets up full Apollo Client with apollo-link-rest but never uses GraphQL. Two HTTP clients (api.ts fetch wrapper + Apollo REST link) doing the same job. Adds ~40KB of unnecessary bundle size.

Critical DEV_TOKEN auth bypass in production code

Both api.ts and client.ts check VITE_DEV_TOKEN. If this env var leaks to production, authentication is bypassed. Custom buildPCToken() generates unsigned JWT.

const devToken = import.meta.env.VITE_DEV_TOKEN;
if (devToken) return devToken; // bypasses Azure AD entirely
Medium No retry, timeout, or request deduplication

Fetch wrapper has no retry mechanism, no request timeout, no caching. Multiple components mounting simultaneously fire identical API requests.

Medium Mixed auth patterns

Two parallel auth flows: MSAL token from Azure AD + custom buildPCToken() unsigned JWT. Some API calls use one, some use the other. Inconsistent security model.

▶ Healthy Patterns 3
Typed API client — api.get<T>, api.post<T>, api.put<T> preserve type safety through request/response.
Consistent error handling — All errors converted to ApiError with Thai messages. Unified { message, code? } shape.
Bearer token from auth store — Centralized token management via Zustand auth store. Single source of truth for auth headers.

4. Hooks (Data Fetching) C+

src/hooks/ (36 hooks, ~5,800 lines)
Largest: useOUMappings.ts (288 lines), usePermissions.ts (267 lines), useEmployees.ts (263 lines)
▶ Anti-patterns 4
High Duplicated CRUD hook boilerplate

15+ hooks repeat identical useState + useEffect + cancelled flag + useCallback refetch pattern. ~60% of hook code is boilerplate. Only URL and type mapping vary.

Medium No caching layer

Every hook fetches data fresh on mount. No request deduplication, no background refetching, no stale-while-revalidate. TanStack Query would eliminate this entire category of issues.

Medium Duplicated snake_case mappers

19 hooks each define inline fromApi/fromApiResponse functions converting snake_case to camelCase. Each mapping is unique but scaffolding is identical.

High No shared CRUD abstraction

36 hooks exist but no useCRUD<T> or createDataHook factory. Each hook manually manages loading, error, data states. Could be reduced to ~10 hooks with a generic factory.

▶ Healthy Patterns 5
Good hook separation — 36 hooks, each focused on a single domain concept. Clear naming convention use<Entity>.
Consistent cancellation — ~20/36 hooks use let cancelled = false pattern to prevent state updates after unmount.
Debounce at hook layer — 7 hooks debounce search queries (300ms) with useRef timer cleanup.
Consistent return shape — All data-fetching hooks return { data, loading, error, refetch }.
Zero console.log — No debug logging left in production code. Clean output.

Medium Modal proliferation (28 modals)

28 modal components represent 41% of all components. Many share confirmation patterns that could be generalized into a reusable ConfirmModal with entity-specific slots.

Self-contained — Each modal manages its own state, validation, and error handling. Good encapsulation.

High Massive inline style usage

High Mixed concerns in page components

Pages contain data fetching, URL sync, export logic, WCAG color calculations, and UI rendering. Hex color validation, luminance calculation, error-code mapping should be in utilities, not inline in JSX.
