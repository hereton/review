Top 3 Critical Findings

1. Docker Runs Dev Server in Production
Dockerfile uses CMD npm run dev instead of building and serving static assets. No production build step. Dev server is unoptimized, no tree-shaking, no minification, no caching headers.
2. Zero Unit Tests — Only 1 E2E Test File
43 hooks, 46 components, 32 modals — none have unit tests. Only tests/e2e/applications.spec.ts (359 lines) exists. No Jest, no Vitest, no React Testing Library configured.
3. No Error Boundaries
Zero ErrorBoundary components in the entire app. Any render error in any component crashes the entire UI with a white screen. No fallback UI, no error recovery.

Top 3 Quick Wins

1. Fix Dockerfile for Production Build (~30 min)
Add multi-stage build: npm run build stage + nginx serve stage. Immediately improves performance, security, and enables proper caching.
2. Add Error Boundary Wrapper (~1 hour)
Add a single ErrorBoundary wrapper in App.tsx around the main content area. Prevents white-screen crashes. No dependency needed — uses React built-in componentDidCatch.
3. Remove Mock Data Imports from Production (~30 min)
App.tsx imports from data/mock.ts (254 lines of mock data) for sidebar counts. Replace with real API calls or remove entirely since useManageUserStats already fetches live data.
