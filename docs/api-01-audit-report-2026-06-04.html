Top 3 Critical Findings

1. Hardcoded Database Credentials
config.go:55 has a default DSN with postgresql://admin:StrongPassword123!@172.31.42.28:8111/mydb committed to version control. Additionally, main.go:172 logs the full DSN to stdout: log.Printf("DEBUG: DATABASE_URL=%q", cfg.DatabaseURL)
2. Certificate Bundled in Docker Image
pc-cert.pfx is copied into the Docker image at /app/secrets/pc-cert.pfx (Dockerfile:33). The comment acknowledges this is only acceptable for dev/POC. Production should mount via Secret Manager.
3. JWT Parsed Without Signature Verification (Production Default)
DevAuthMiddleware is the default production auth path. It calls parseJWTPayloadUnsafe() which base64-decodes the JWT payload without checking signature or expiry. Trust relies on network boundary (VPN/internal). ACL middleware is not yet wired — 6+ TODO comments reference this gap.

Top 3 Quick Wins

1. Remove Hardcoded Credentials & DEBUG Logging (~30 min)
Remove default DSN from config.go (fail fast if DATABASE_URL unset), remove DEBUG: DATABASE_URL log line from main.go:172. Zero code risk.
2. Add golangci-lint Configuration (~1 hour)
Add a .golangci.yml with errcheck, govet, staticcheck, and revive linters. Add lint: stage to .gitlab-ci.yml. Catch common issues at CI time.
3. Move Certificate to Secret Manager Mount (~2 hours)
Remove COPY pc-cert.pfx from Dockerfile. Mount via Cloud Run secret volume. Eliminates cert from image layers permanently.
