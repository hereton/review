▶ Anti-patterns 2
High Dual status columns on roles table

The roles table has both status VARCHAR(20) (active/inactive) and deleted_at TIMESTAMPTZ — two competing lifecycle mechanisms creating split-brain risk.

migrations/000008_add_status_deleted_at_to_roles.up.sql
ALTER TABLE roles
    ADD COLUMN IF NOT EXISTS status     VARCHAR(20)  NOT NULL DEFAULT 'active',
    ADD COLUMN IF NOT EXISTS deleted_at TIMESTAMPTZ  NULL;
Medium Data migrations mixed with schema migrations

13 of 56 migration files contain INSERT/UPDATE/DELETE alongside schema DDL, making rollback harder and violating separation of concerns.

▶ Healthy Patterns 5
Good BIGSERIAL identity columns throughout

All tables use BIGSERIAL PRIMARY KEY for consistent 64-bit auto-increment identity.

Good TIMESTAMPTZ used consistently

All timestamp columns use timezone-aware TIMESTAMPTZ — no plain timestamp anywhere.

Good Proper ENUM types for bounded domains

permission_type, sync_status, sync_trigger, sync_type are proper PostgreSQL ENUMs rather than VARCHAR with comments.

Good Normalized 3NF design

No god tables (>30 columns). Junction tables properly separate many-to-many relationships. Permission presets normalized from JSONB to relational table (migration 000056).

Good IF NOT EXISTS guard on DDL

CREATE TABLE IF NOT EXISTS and ADD COLUMN IF NOT EXISTS used throughout — resilient to partial re-runs.

▶ 3.2 Constraints & Integrity B
▶ Anti-patterns 2
High No CHECK constraints on status VARCHAR columns

Tables using status VARCHAR(20) (roles, permissions, applications, ou_role_mappings, abac_delegations, user_abac_assignments) have no CHECK constraint to enforce allowed values. Invalid statuses can be inserted freely.

High Composite FK lacks index on abac_divisions(bu_id, id)

user_abac_assignments references abac_divisions(bu_id, division_id) via composite FK, but the index coverage should be verified for join performance.

▶ Healthy Patterns 4
Good 53 foreign keys with appropriate CASCADE/SET NULL

Comprehensive FK coverage. Most use ON DELETE CASCADE for dependent records; SET NULL for nullable references (audit_logs.application_id, abac_roles.rbac_role_id).

Good UNIQUE constraints on natural keys

Composite UNIQUE on (application_id, code) for roles and permissions. Unique on applications.code, users.oid, abac_bus.code, abac_divisions.code.

Good Partial unique indexes for business rules

uq_delegation_active enforces uniqueness only on active delegations. uq_uabac_active enforces uniqueness only on active ABAC assignments. Clever use of partial indexes for conditional uniqueness.

Good Consistent NOT NULL with defaults

Core columns are NOT NULL with sensible defaults (created_at DEFAULT NOW(), is_active DEFAULT TRUE, status DEFAULT 'active'). Nullable used strategically for optional data only.

▶ 3.3 Indexing Strategy A-
▶ Anti-patterns 1
Medium Some FK columns may lack dedicated indexes

With 53 FKs and 89 indexes, coverage is good, but individual FK column index verification is recommended for join-heavy queries (e.g., role_permissions.permission_id).

▶ Healthy Patterns 4
Good 15 partial indexes for active-record queries

WHERE is_active = TRUE, WHERE deleted_at IS NULL, WHERE status = 'active' — dramatically reduces index size for the common query path.

Good Composite indexes aligned with query patterns

idx_permissions_application_id_type, idx_roles_application_id, composite indexes on ABAC tables — match the WHERE/JOIN clauses in repository code.

Good IF NOT EXISTS on all index creation

All CREATE INDEX statements use IF NOT EXISTS — safe for re-runs and rollback/re-apply scenarios.

Good Time-based indexes for expiration tracking

Indexes on expires_date with WHERE clauses enable efficient cleanup queries for expired assignments and delegations.

▶ 3.4 Migration Management B
▶ Anti-patterns 3
Critical ENUM type extensions are irreversible

Migration 000050 adds 3 values to sync_type ENUM. PostgreSQL ALTER TYPE ADD VALUE cannot be reversed without recreating the type — the down migration is a no-op placeholder.

migrations/000050_extend_sync_type_enum_for_abac.up.sql
-- NOTE: In PostgreSQL, adding values to an ENUM is irreversible.
-- The down migration cannot remove these values without recreating the type.

ALTER TYPE sync_type ADD VALUE IF NOT EXISTS 'abac_master';
ALTER TYPE sync_type ADD VALUE IF NOT EXISTS 'abac_assignment';
ALTER TYPE sync_type ADD VALUE IF NOT EXISTS 'abac_delegation';
High 6 tables dropped in production migrations

token_sessions, ad_groups, user_ad_groups, menus, role_menu_mappings, permission_center_migrations, permission_center_seeds all dropped. While down migrations recreate them, data loss is permanent on forward migration.

Medium Data migrations mixed with schema DDL

7 files contain INSERT, 6 contain UPDATE alongside schema changes. Migration 000026 converts is_active to status. Migration 000034 converts updated_by from user_id to name. Migration 000056 normalizes JSONB to relational table.

▶ Healthy Patterns 3
Good All 56 migrations have matching up/down pairs

100% rollback coverage. Every .up.sql has a corresponding .down.sql. Down migrations properly recreate dropped tables, re-add dropped columns, and reverse data changes.

Good Sequential 6-digit numbering

000001 through 000056 — clean, ordered, no gaps. Easy to understand sequence and locate specific migrations.

Good Idempotent seed migrations

ON CONFLICT DO NOTHING used in all seed files. Safe to re-run without duplicate key errors.

▶ Healthy Patterns 5
Good Zero SELECT * usage

All queries use explicit column selection via GORM Select() or named columns in Raw() SQL. No SELECT * anywhere in the codebase.

GORM query builder and Raw() with ? placeholders throughout. LIKE patterns use escapeLike() helper (role_repository.go:409).

Good Proper transaction boundaries

Multi-table writes use GORM Transaction() with automatic rollback: manage_user_repository (role assignment), role_permission_repository (permissions + audit), user_abac_assignment_repository (archive + insert).

Good Context propagation throughout

All repository methods accept ctx and use r.db.WithContext(ctx). Enables request cancellation, timeout propagation, and tracing.

▶ 3.6 Soft Delete & Lifecycle C
▶ Anti-patterns 3
Critical Three different soft-delete strategies across tables

Inconsistent lifecycle management makes querying error-prone:

  • deleted_at (GORM soft delete): roles only
  • status VARCHAR(20) ('active'/'inactive'): roles, permissions, applications, ou_role_mappings, abac_delegations, user_abac_assignments
  • is_active BOOLEAN: users, abac_bus, abac_divisions, abac_roles, delegation_pair_configs
High Dual status on roles: deleted_at + status

The roles table has both GORM DeletedAt (deleted_at) and a manual status column. A role could be status='active' with deleted_at set, or status='inactive' with deleted_at=NULL — contradictory states.

Medium Hard delete on some tables, soft delete on others

ou_role_mappings uses status='inactive' for soft delete. user_role_assignments uses hard DELETE. No consistent policy for which tables should preserve history.

▶ Healthy Patterns 1
Good archived_at for ABAC assignment history

user_abac_assignments uses archived_at TIMESTAMPTZ for soft-delete with timestamp — a better pattern than deleted_at as it conveys intent (archive, not delete).

▶ 3.7 Naming Conventions B-
▶ Anti-patterns 3
High updated_by type changed mid-stream (BIGINT FK → VARCHAR)

Migration 000034 converted updated_by from "user:<id>" pattern to actual user name (VARCHAR). This is a naming scar — the column holds different data types across its history.

migrations/000034_fix_updated_by_user_id_to_name.up.sql
UPDATE roles r
SET updated_by = u.name
FROM users u
WHERE r.updated_by = 'user:' || u.id::text;
Medium Inconsistent lifecycle column names

Same concept (is this record active?) uses different names: is_active, status, deleted_at, archived_at across tables.

Medium created_by vs actor_user_id inconsistency

role_permission_presets uses actor_user_id. ou_role_mappings uses created_by. Both track who created the record but with different column names.

▶ Healthy Patterns 3
Good Consistent snake_case throughout

All table names are plural snake_case. All column names are snake_case. No camelCase or PascalCase in SQL identifiers.

Good Same-concept-same-name for most columns

application_id, user_id, role_id, created_at, updated_at are consistent across all tables. Foreign key columns match the referenced table's id column naming.

Good Descriptive index names with prefix convention

idx_ prefix for standard indexes, uq_ prefix for unique indexes. Names include table and column context (e.g., idx_abac_bus_active, uq_delegation_active).
