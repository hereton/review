Top 3 Critical Findings

1. Zero Tests — No Unit, No E2E, No Test Runner
156 TS/TSX files, 26 hooks, 78 components, 26 modals — none have any test coverage. No Vitest, Jest, Playwright, or React Testing Library configured. No test scripts in package.json. Critical risk: any refactor could silently break business logic.
2. 27 God Components Exceeding 300 Lines
27 files exceed the 300-line threshold. The largest, PolicyWizardModal.tsx (1,739 lines), implements a 4-step wizard with template picking, form state, condition builder, CEL parsing, user search, and preview in a single file. 4 files exceed 1,000 lines.
3. 1,439 Inline Styles Across 63 Files
40% of TypeScript files use style={{}} despite Tailwind CSS being configured. Mixing inline styles with utility classes creates maintenance burden, defeats Tailwind's purpose, and makes responsive design harder.

Top 3 Quick Wins

1. Add Error Boundary Wrapper (~1 hour)
Wrap RouterProvider in main.tsx with an error boundary. Prevents white-screen crashes. Use React's built-in componentDidCatch or react-error-boundary.
2. Add ESLint + Prettier (~1 hour)
No linter or formatter configured. 13 eslint-disable comments exist without a linter. Configure eslint with React + TypeScript rules and prettier for consistent formatting.
3. Add Code Splitting with React.lazy (~2 hours)
All 25 pages + 13 tabs loaded eagerly. Zero React.lazy or Suspense usage. Lazy-load page components in routes/index.tsx to reduce initial bundle size.
