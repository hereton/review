Top 3 Critical Findings

1. Hardcoded Database Credentials in Source Code
config.go:60 contains a hardcoded PostgreSQL password in defaultDatabaseURL(). Additionally, seed_delegation_pairs and fix_migration CLI tools have hardcoded DSNs.
2. panic() in Auth Middleware Startup Path
auth_middleware.go:136,144 uses panic() instead of returning errors when JWKS initialization fails. Application crashes with no graceful degradation.
3. Production Auth Middleware Commented Out
main.go:222-226 has the real AuthMiddleware(cfg) call commented out. If no MOCK/DEV flags are set, requests bypass all authentication entirely.

Top 3 Quick Wins

1. Uncomment Auth Middleware (~5 min)
Uncomment v1.Use(middleware.AuthMiddleware(cfg)) in main.go. Requires AZURE_TENANT_ID and AZURE_CLIENT_ID env vars in production.
2. Add .golangci.yml (~15 min)
Add a linter config to catch errcheck, gocritic, revive warnings. Zero code changes, immediate static analysis coverage.
3. Remove Hardcoded Credentials (~10 min)
Remove defaultDatabaseURL() fallback, require DATABASE_URL env var. Remove hardcoded DSNs from CLI tools.
