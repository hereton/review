    SVC[Service Method]

    SVC -->|single tx| UOW[Unit of Work]
    UOW -->|shares tx| R1[Repo A]
    UOW -->|shares tx| R2[Repo B]
    UOW -->|shares tx| R3[Repo C]

    style UOW fill:#ecfdf5,stroke:#059669
Problem

Services can't coordinate transactions across repositories — each repo manages its own tx, creating a consistency gap for multi-step mutations.

Solution

Introduce Unit of Work pattern: service begins a transaction context and passes it to all repositories, ensuring atomic commit/rollback across repos.

atomic multi-repo ops consistency guarantee simpler rollback clearer tx boundaries

Top Recommendation

Start with

C1: Extract Authorization Middleware

Why first

Highest impact, lowest risk. No schema changes, no data migration. Touches only handler files. Removes scattered auth checks from 5+ files into a single middleware seam. Every new endpoint benefits immediately.

Recommended order
  1. 1 C1 Authorization Middleware — Presentation layer
  2. 2 C2 Audit Decorator — Application layer
  3. 3 C3 Domain Enrichment — Domain layer
  4. 4 C4 Query Consolidation — Infrastructure layer
  5. 5 C5 Transaction Coordination — if needed
Layer dependency order: Presentation depends on Application depends on Domain. Infrastructure implements Domain interfaces. Work inside-out: Domain changes propagate safely; Presentation changes are isolated.
