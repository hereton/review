Top 3 High Findings

1. Repository Layer Has Zero Unit Tests
14 repository files (~3,391 lines) with complex JOIN queries, CTE aggregations, and advisory locking — none have unit tests. Only integration test infrastructure exists (testcontainers), but no tests are written.
2. String Interpolation for Dynamic Query Conditions
Repositories build WHERE clauses with fmt.Sprintf for dynamic filters. While values use parameters, column names and conditions are interpolated, risking SQL injection if filter keys are ever user-controlled.
3. No Rate Limiting or Circuit Breaker Middleware
No rate limiting on any endpoint. Microsoft Graph API calls have no circuit breaker — repeated upstream failures could cascade and exhaust connection pools. OTEL dependencies present but not configured.

Top 3 Quick Wins

1. Add Repository Unit Tests with go-sqlmock (~1-2 days)
Project already has go-sqlmock as a dependency. Start with the 4 largest repos (org_rule 437, pc_admin 408, assignment 401, ou_app_mapping 395 lines).
2. Add Rate Limiting Middleware (~2 hours)
Add x/time-based or gin-contrib/limiter rate limiter. Apply globally or per-route. Zero code changes to handlers/usecases.
3. Add Connection Pool Configuration (~30 min)
Add SetMaxOpenConns, SetMaxIdleConns, SetConnMaxLifetime to infrastructure/database/postgres.go. DB_MAX_CONNS env var exists but isn't applied.
