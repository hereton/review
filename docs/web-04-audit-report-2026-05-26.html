Executive Summary

Top 3 Critical Findings

1 Zero test coverage — 0 unit tests, 0 integration tests. Only 1 E2E test file exists. Any refactoring or bug fix has no safety net.
2 No routing library — Navigation uses useState for section/tab. No URL updates, no browser back/forward, no deep linking.
3 1,077 inline style={{}} objects across the codebase. Creates a maintenance burden, inconsistent styling, and cannot be overridden by CSS.

Top 3 Quick Wins

1 Add react-router — Replace useState navigation with proper routing. Enables URL sharing, browser history, and code splitting.
2 Add vitest + @testing-library/react — Start with testing hooks (34 pure logic modules) and shared components. Highest ROI for initial test coverage.

3. API Layer C+

src/lib/api.ts (59 lines — fetch wrapper)
src/lib/auth.ts (~56 lines — JWT token handling)
▶ Anti-patterns 4
Critical Hardcoded production URL as fallback

api.ts:1 — Fallback URL couples deployments to a specific Cloud Run instance. Changing environments requires code changes.

const BASE_URL = import.meta.env.VITE_API_BASE_URL ??
  'https://permission-center-api04-927334225598.asia-southeast1.run.app';
Critical DEV_TOKEN auth bypass in production build

Both api.ts and auth.ts check VITE_DEV_TOKEN. If this env var leaks to production, authentication is bypassed entirely. No build-time stripping.

Medium No retry, timeout, or request deduplication

Fetch wrapper has no retry mechanism, no request timeout, and no caching/deduplication. Multiple components mounting simultaneously fire identical API requests.

Medium Presentation concern in infrastructure

toast.ts exports useToastStore() React hook — UI state management in the infrastructure layer.

▶ Healthy Patterns 3
Typed API client — api.get<T>, api.post<T> preserve type safety through request/response.
Consistent error handling — All errors converted to ApiError with Thai messages. Unified { message, code? } shape.
Clean JWT decode — No external library dependency. Simple base64 decode with fallbacks.

Package Recommendations

Area Current Recommended Confidence Why
Routing useState react-router v7 Strong URL-based navigation, browser history, code splitting, deep linking. Essential for any multi-page SPA.
Data Fetching fetch + 34 custom hooks @tanstack/react-query Strong Eliminates ~60% of hook boilerplate (cancellation, refetch, caching, dedup, loading states). Team already uses @tanstack/react-virtual.
Forms useState per field react-hook-form + zod Strong 29 modals with forms, each with manual state + validation. RHF reduces form code by ~50%. Zod provides type-safe schemas shared with API types.
Global State Prop drilling zustand Strong Minimal API, no boilerplate. For sidebar state, user profile, app counts. Much lighter than Redux for this scope.
Unit Testing None vitest + @testing-library/react Strong Vitest integrates natively with Vite. Start with 34 hooks (pure logic, easy to test) and shared components.
Error Boundaries None react-error-boundary Worth Exploring Wrap route-level components. Prevents full-page crash from runtime errors. Lightweight, well-maintained.
Linting None eslint + prettier Worth Exploring Enforce consistent style, catch bugs early. 12 eslint-disable comments suggest rules would catch real issues.
