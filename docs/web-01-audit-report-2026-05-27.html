All types (50+ type definitions) live in a single types.ts. This includes domain models, API DTOs, request/response types, and entity types for employees, roles, permissions, delegations, groups, attributes, and OU mappings. Should be split into types/role.ts, types/permission.ts, etc.

3. API Layer C+

src/lib/api.ts (75 lines — REST fetch wrapper)
src/apollo/client.ts (39 lines — Apollo Client + REST link)
src/apollo/queries/auth.ts (23 lines)
▶ Anti-patterns 2
High Dual HTTP clients — Apollo + raw fetch

The app uses both apolloClient (Apollo Client with REST link) and api.ts (raw fetch wrapper) for REST calls. Hooks exclusively use api.ts, making the Apollo Client setup largely unused. Should consolidate to one client.

Medium No request interceptor or error standardization

api.ts has basic error wrapping but no retry logic, request deduplication, or centralized error boundary. Each hook handles errors individually with setError(e?.message ?? '...') boilerplate.

▶ Healthy Patterns 3
Clean REST wrapper — api.ts provides typed get/post/put/patch/delete methods with automatic auth header injection and error wrapping.
Dev bypass token support — VITE_DEV_BYPASS env var allows local development without Azure AD. Clean developer experience.
JWT-based auth with Zustand store — Token stored in Zustand with sessionStorage persistence. Auto-decoded via jwt-decode.

▶ Anti-patterns 3
High CRUD hook boilerplate duplication

Each entity (Permissions, Roles, OUMappings, Employees, Delegations) has 4-5 separate hooks for list/get/create/update/delete with nearly identical patterns: useState + useCallback + api.get/post/put/delete + fromApiResponse mapper. ~15 hooks could be replaced by a generic useCrud<T>(baseUrl) factory.

// Repeated in usePermissions.ts, useOUMappings.ts, useRoles.ts, etc:
const [loading, setLoading] = useState(false);
const create = useCallback(async (input) => {
  setLoading(true);
  try { return fromApiResponse(await api.post(...)); }
  finally { setLoading(false); }
}, [appCode]);
Medium Manual debounce implementation

usePermissions.ts manually implements debouncing with useRef + setTimeout + clearTimeout. A reusable useDebounce hook or useDeferredValue would eliminate this boilerplate.

Medium No caching or stale-while-revalidate

All data fetching hooks use raw useState + useEffect with no caching. Navigating away and back triggers a full refetch. Apollo Client's InMemoryCache is configured but unused for REST calls.

▶ Healthy Patterns 5
Well-separated concerns — 37 hooks, each focused on a single entity/feature. No god hooks.
Proper cleanup patterns — All useEffect fetch hooks use cancelled flag pattern to prevent state updates on unmounted components.
Typed API mappers — Each hook defines a fromApiResponse() function converting snake_case API DTOs to camelCase domain types.
Refetch via tick counter — useCallback(() => setTick(n => n+1), []) pattern avoids stale closures while providing refetch() to consumers.
Loading/error state — Every data hook exposes { data, loading, error, refetch }. Consistent interface.
